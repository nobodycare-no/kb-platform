# 技术白皮书 —— kb-platform 工程实践与生产级设计

> 本文档面向技术评审者，系统阐述 kb-platform 在真实生产约束下所做的架构决策、
> 缺陷驱动的工程修正、以及可复现的质量证据。设计背景详见 [SAD](./sad/SAD.md)（含 7 条 ADR）。

---

## 1. 系统构成

8 容器 compose 拓扑：`web(nginx) / backend(FastAPI) / ai-service(FastAPI) /
MySQL 8 / Redis 7 / Milvus standalone(etcd+minio)`，推理平面为外部 GPU 服务
（vLLM Qwen3-8B + bge-m3 + bge-reranker，全 HTTPS + API Key，地址全 env 化）。

核心代码量分布（实测）：backend ≈ 2.0k 行、ai-service ≈ 0.9k 行、web(src) ≈ 1.0k 行、SQL/部署 ≈ 0.2k 行，合计 ≈ 4.0k 行。

## 2. 十个生产级问题 → 工程解法映射

### 2.1 制度类语料的"精确条款"与"口语描述"双形态查询

**问题**：纯向量检索对"第几条""专有名词"类查询召回差；纯关键词对口语化描述召回差。
**解法**：双路并发召回（Milvus 稠密 top50 ∥ MySQL ngram FULLTEXT top20）+ RRF(k=60) 融合。
**关键工程点**：初版用 `asyncio.gather` 耦合两腿，关键词腿 200ms 超时会**连坐取消已完成的
稠密任务**——改为独立 `create_task`，熔断只弃己路（回归测试锁定该行为）。
**实测**：混合召回使制度条款类问题命中从"偶发"提升至黄金集 14/14 全中。

### 2.2 敏感知识越权访问

**解法**：四维权限实体（global/department/role/user，OR 语义）在**召回后、重排前**
强制过滤；默认拒绝；未授权单元仅返回"存在缺失"提示而不进入任何下游环节。
**性能**：判定走 Redis 快照（key 含授权三表 watermark，变更自然失效），热态 ≤5ms；
冷态回源批量 IN 查询，实测均值 26.5ms（NFR-02 目标 50ms）。
**测试**：16 行数据驱动判定矩阵 + 双模认证端点 E2E。

### 2.3 单一 LLM 端点的可用性风险

**解法**：ModelGateway 统一收敛三类模型调用；LLM 连续失败 N 次（可配）后**粘性切换**
备用 OpenAI 兼容端点（仅在首 delta 前切换，避免输出重复）；embedding 故障自动降级
纯关键词检索并在响应标注降级态。全部经 httpx.MockTransport 注入式单测覆盖。

### 2.4 向量库作为"唯一真相"的运维噩梦

**解法**：ADR-003 —— MySQL 为事实源，Milvus 仅存派生索引；写路径先正本后索引，
失败任务可重试；提供 `reindex` CLI 一键全量重建（实测 4/4 单元重建成功）。
配套 **schema 对齐守卫测试**：解析 init.sql 列集合与 ORM metadata 双向比对，
上线路前即捕获两处真实漂移。

### 2.5 微服务间信任边界

**解法**：ai-service 不持有 MySQL 凭据；权限判断通过回调 backend 完成——保证
权限规则全局只有一份实现。服务间认证使用 X-Internal-Token 常量时间比较；
鉴权回调端点采用**双模认证**（内部令牌可代查任意用户 / JWT 仅限本人，
超管旁路）——该设计修复了链路联调期的认证死锁。

### 2.6 小参数模型的幻觉控制

三层缓解：
1. **检索层门控**：重排最高分低于阈值直接短路拒答（拦截完全无关 query，实测股票类问题 score=0.0 被拦）；
2. **生成层约束**：结构化拒答 Prompt + 「片段外数值一律未知」显式规则 +
   Qwen3 `<think>` 思考链流式过滤状态机（处理跨 chunk 半标签边界）；
3. **评估层闭环**：RAGAS 五指标量化迭代（见 §4），faithfulness 短板已定位并排期 groundedness 校验链。

### 2.7 配置漂移与环境差异

所有易变项（模型地址、密钥、检索参数、集合名）收敛至 `.env`，`.env.example`
为字段唯一清单；Milvus 集合名纳入 Settings 支持**测试命名空间隔离**（修复
8 维测试数据写入 1024 维生产集合的事故）；语料目录支持 env 重定向并挂载进容器。

### 2.8 测试金字塔与验收自动化

| 层 | 数量 | 手段 |
|----|------|------|
| 单元 | 权限矩阵×16 / RRF×4 / chunker×10 / FAQ 归一×5 / Gateway 协议×11 | 数据驱动参数化 |
| 集成 | 认证×6 / 组织 RBAC×7 / 导入管线×5 / schema 对齐×14 | SQLite 内存库 + MockTransport |
| E2E | 三真实进程微服务拓扑 ×1 | 真实 MySQL FULLTEXT + 真实 Milvus + 模型 Mock |
| 验收 | 部署栈探针 ×28 断言 | 对 web:8081 统一入口黑盒执行 |

**教训沉淀**：① FastAPI 值注入依赖返回 Response 不短路 → 全面改 ApiError 异常模式；
② SQLite 对 BigInteger 主键无 ROWID 别名 → 可移植 Integer 主键；③ 构建期 pyc 污染
→ .dockerignore 强制排除。

### 2.9 可观测性

- `/health/models` 三依赖独立探测（2s 超时、延迟采样）；
- `qa_access_logs` 全量留痕：召回/授权/未授权三组 ID + Token 计数 + 耗时 + 降级标记，
  同时支撑看板聚合与 RAGAS 取证；
- `[perm-debug]` 运行时诊断开关（曾用于定位权限缓存事故现场）。

### 2.10 评估驱动的迭代（RAGAS 闭环）

五轮「评估 → 发现 → 针对性调整」完整记录于[测试评估报告](./测试评估报告.md) §3：
口径校准 → 相关性门控 → Prompt 数值禁编规则，行为命中率 9/12 → 18/19，
并产出五指标量化基线（judge=Qwen3-8B@vLLM）：

| faithfulness | answer_relevancy | context_precision | context_recall | answer_correctness |
|---|---|---|---|---|
| 0.496 | 0.607 | **0.851** | **0.885** | 0.653 |

结论符合课件定位法：检索侧健康（双高），短板集中于小尺寸生成模型的忠实度，
已规划 groundedness 校验链（v1.1）。

## 3. 关键选型速览与理由

| 决策 | 选择 | 否决项及原因 |
|------|------|-------------|
| 向量库 | Milvus standalone | Qdrant（更轻但生态诉求）、pgvector（与既定"MySQL+独立向量库"冲突）；检索层接口化，可无痛替换 |
| SSE vs WebSocket | POST + SSE 流 | WebSocket 双端状态复杂；POST 才能携带大 JSON 体；nginx 关缓冲即可透传 |
| 服务拆分 | AI 网关独立进程 | 模型的 GPU 依赖/多协议/换址三大易变因素收敛隔离（ADR-001） |
| JWT 库 | python-jose + 直用 bcrypt | passlib 在 py3.13 的维护停滞问题 |
| 图表渲染 | Mermaid in Markdown | GitHub 原生渲染零工具链（PlantUML 需本地环境） |
