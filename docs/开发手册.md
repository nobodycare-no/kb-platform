# kb-platform 实施计划（开发手册）

> **执行方式**：本计划由 ox-alpha 在会话内按切片顺序执行（executing-plans 模式），每个任务以复选框跟踪，完成即提交。

**Goal:** 三天内交付企业级知识库管理平台 v1.0：鉴权 RAG 问答、四维数据权限、FAQ 沉淀闭环、数据看板、docker-compose 部署。

**Architecture:** CPU 平面三服务（web/backend/ai-service）+ MySQL/Redis/Milvus；GPU 平面 AutoDL 三模型全 env 化接入。详见 `docs/sad/SAD.md`。

**Tech Stack:** FastAPI · SQLAlchemy 2 · Vue3+Vite+Element Plus · MySQL 8 · Redis 7 · Milvus 2.4 standalone · pytest · RAGAS

**Spec:** `docs/srd/SRD.md`（FR/AC 编号在任务中引用）· `docs/sad/SAD.md` · `docs/sdd/SDD.md`

## Global Constraints

- 容器内 Python 固定 `python:3.11-slim`（宿主机 3.13 仅用于本地脚本）；Node ≥ 20（本机 24）。
- 端口：web→`8081:80` 唯一宿主映射；backend 8000 / ai-service 8001 / mysql 3306 / redis 6379 / milvus 19530 **仅 compose 内网**。
- 所有密钥/地址只出现在 `.env`（根目录 `.env.example` 为唯一字段清单，见 SDD §8，不在此重复）。
- 服务间认证常量名：`X-Internal-Token`；JWT：HS256、12h、claim=`{sub, username, department_id, role_ids, permission_codes}`。
- 提交规范：`feat|fix|test|docs|chore(scope): msg`；每个任务绿测后提交；里程碑打 tag。
- TDD 强制范围：`chunker` / `rrf` / `permission_engine` / `faq 归一化hash` / `model_gateway 重试切换`；CRUD 走集成冒烟。
- 统一响应包 `{code, message, data}`；错误码分段见 SDD §5。
